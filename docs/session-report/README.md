# Session report — design assets

- `mockup.html` — approved-direction mockup of the client history + session report (sample data).
- `hq_{male,female}_{front,back}.png` — body maps for the muscle map, 1400 px tall, symmetric (left half mirrored).
  R = region, G = shade (0..255, dome per muscle, for volume), B = silhouette coverage (anti-aliased alpha). R values:
  `0` outside, `1..10` = suit channel + 1 (PartStrenthBean.buwei order: 0 chest, 1 abs, 2 front thigh,
  3 calf, 4 arms, 5 traps, 6 back, 7 lower back, 8 glutes, 9 back thigh), `11` other muscle (not a channel),
  `12` body. Recolor per pixel by channel dose (5 discrete steps: blue, cyan, green, yellow, red — no orange),
  colour × (0.52 + 0.62·shade^0.8) + highlight above shade 0.78; draw scaled with smoothing;
  glow = blurred copy of the hottest channels under the figure. Generated by `tools/` (seg → segm3 → assign2 → export2).
- Sources: user-supplied reference art (male: segmented blue/grey figure; female: pink/black figure), segmented
  by colour, components assigned to channels by position.

## Implementation (1.1.156-ai)

- `wearable/SessionRecorder` — 1 s tick (started from `XemsPanel.attach`). Per slot with a client: a training starts
  on Start (`data.start`); pause = start off while `TrainItem.workLength` (seconds left) keeps its value; end = start
  off and the countdown back at the plan (reset) or 0, another client in the slot, or a pause > 30 min. Under 60 s of
  work → dropped. `data.inStart` toggles with the impulse / pause part of the ON/OFF cycle → column `imp`.
- The first running slot is the band wearer: heart rate (`HrHistory`, fresh < 8 s), Smart Session phase, 60 s of
  recovery HR after the end, and `BandWorkout` (native band workout, only when the client is marked band owner).
- `wearable/SessionRec` columns per second: run, imp, hr, st (main strength), ch[10] (buwei %), dis (disabled
  bitmask), hz, pw, on, off, ap, ps, phz, ph (AI phase 1..4); plus post (HR after the end), person, band, chPeak.
- `wearable/SessionStore` → `files/xems_sessions/index.json` + `s_<id>.json`.
- `wearable/ReportScreen` → full-screen WebView on `assets/report/session-report.html`
  (`branding/report/`, shipped by `scripts/apply-session-report.py`); `ReportBridge` = `window.XemsReport`
  (client, sessions, session, putScores, deleteSession, close, theme, focus).
- Entry: client form → "История и доклади"; card "Гривна и Mi Fitness" (band owner, sport code; prefs
  `xems_user_profiles`: `own<id>`, `misport<id>`).
- All maths (stimulus S, HR reserve C, intensity, modes, efficiency, load, kcal, recovery) run in the page — see the
  "Как се смята" section there. Channel tolerance = the client's highest real strength per channel in any session.

## Share / export (1.1.157-ai)

"Сподели" in the report header: PNG card 1080×1350 (canvas, dark), PDF (system print dialog on the WebView,
page switched to the light theme with print CSS), short text, TCX (`Sport="Other"`, HR every 5 s, calories — Strava
upload, Garmin Connect import, TrainingPeaks, Intervals.icu, Runalyze), CSV per second and CSV client history
(`;` separated, UTF-8 BOM for Excel). Files go through `ReportBridge.shareFile` → cache/xems_share →
FileProvider `<package>.provider` (manifest `root-path`) → ACTION_SEND chooser.
Health Connect / Google Fit direct writing is not done: it needs the Health Connect client and new manifest permissions.
