# XEMS — лиценз, отключване на модули и обновяване (клиент v1.1.85)

Клиентската част е готова. Сървърът ще се напише по този документ. Докато сървърът липсва, приложението работи офлайн: в базов режим или отключено с код.

## Модули

| id | Модул | Какво заключва |
|---|---|---|
| `timer` | Таймер | плочката „Таймер“ |
| `music` | Музика | плочката „Музика“ (плейър и импулси по музиката) |
| `pulse` | Пулс | плочката „Пулс“ и автоматичното намаляване на силата по пулса |
| `ai` | AI | плочката „AI тренировка“ |
| `band` | Часовник | управлението от гривната (музикалният екран), приложението на гривната и инсталирането му |

**Функции** (`feat`) са отделни от модулите: включват или изключват поведение, а не екран.

| id | Функция |
|---|---|
| `arms_full` | каналът за ръцете (индекс 4) се праща 1:1, с нормална сила; без нея се праща ×0.05. AI сметките следват същото. |

- **Базов режим** (нова инсталация): тренировката работи. Плочките на модулите се виждат с 🔒, а натискането им дава „Нямате достъп до този модул“.
- **Гривна:** свързва се и настройките ѝ се показват само ако е отключен `pulse`, `ai` или `band`.

## Отключване

Настройки → **Достъп и лиценз** → поле **Потребителски ключ** → **Активирай**.

1. **Ключ `0123`:** офлайн, отключва всичко, без срок. Константата е `XemsLicense.LOCAL_CODE`.
   **Ключ `reni123`:** офлайн, базов режим + функцията `arms_full` (ръцете с нормална сила). Константата е `LOCAL_CODE_ARMS`.
   Главни и малки букви са без значение.
2. **Друг ключ:** отива към сървъра, `POST /v1/license/activate`. Сървърът отговаря с подписан жетон.
3. **Празен ключ + Активирай:** връщане в базов режим.

Жетонът се пази и проверява офлайн: подпис, устройство, срок. Когато има сървър, се опреснява веднъж на 24 часа (`/v1/license/refresh`). Без сървър работи до крайната дата плюс **7 дни** гратисен период; след това модулите се заключват.

## Данни, които клиентът праща (входни данни за сървъра)

Всяка заявка съдържа:

| поле | тип | пример | откъде |
|---|---|---|---|
| `device_id` | string (16 hex) | `7F3A91C20B55D1E4` | SHA-256(ANDROID_ID + „\|“ + package), първите 16 знака; случаен, ако няма ANDROID_ID. Показва се в Настройки като `7F3A-91C2-0B55-D1E4`. |
| `device_model` | string | `samsung SM-T505` | Build.MANUFACTURER + MODEL |
| `android` | int | `30` | Build.VERSION.SDK_INT |
| `app_version` | string | `1.1.83-ai` | versionName |
| `app_code` | int | `208` | versionCode |
| `lang` | string | `bg` / `en` | езикът на приложението |

## API (HTTPS, JSON, UTF-8)

Базовият адрес е в `XemsLicense.DEFAULT_SERVER` или в полето Настройки → Лиценз → „Сървър ›“. Празен адрес означава офлайн.

### 1. Активиране

```
POST {server}/v1/license/activate
{"device_id":"7F3A91C20B55D1E4","device_model":"samsung SM-T505","android":30,
 "app_version":"1.1.83-ai","app_code":208,"lang":"bg","key":"XEMS-7K2P-9QWD"}

200 {"ok":true,"token":"<жетон>"}
4xx {"ok":false,"error":"invalid_key","message":"…"}
```

Кодове за грешка, които клиентът показва на човешки език:

| код | значение |
|---|---|
| `invalid_key` | ключът не съществува |
| `expired` | ключът е изтекъл |
| `device_limit` | ключът вече е ползван на максималния брой устройства |
| `revoked` / `disabled` | ключът е спрян |

### 2. Опресняване (веднъж на 24 h, във фон)

```
POST {server}/v1/license/refresh
{…общите полета…, "token":"<текущият жетон>"}

200 {"ok":true,"token":"<нов жетон>"}
4xx {"ok":false,"error":"revoked"}   → клиентът се връща в базов режим
```

- `revoked` или `unknown` → заключване.
- Друга грешка или липса на мрежа → текущият жетон остава.

### 3. Проверка за нова версия

```
GET {server}/v1/app/update?app=xems&channel=stable&code=208&device_id=7F3A91C20B55D1E4

200 {"ok":true,"version_code":215,"version_name":"1.1.90-ai",
     "url":"https://…/xems-1.1.90-ai.apk","sha256":"<64 hex>","size":9117486,
     "notes":"Какво е ново…","mandatory":false}
```

- **Нова версия** е тази, чийто `version_code` е по-голям от текущия, а `url` започва с `https://`.
- **При старт** (`XemsLicenseClient.autoCheck`): най-много веднъж на 12 часа, само с адрес на сървър. Ако има нова версия, излиза прозорец „Изтегли и инсталирай“ / „По-късно“. „По-късно“ пропуска тази версия; при `mandatory:true` го няма.
- **Изтегляне:** с бутона „Изтегли и инсталирай“, в кеша на приложението.
- **Проверка:** SHA-256 спрямо `sha256`. При разлика файлът се изтрива.
- **Инсталиране:** предава се на системния инсталатор (FileProvider `…updateFileProvider`, правото REQUEST_INSTALL_PACKAGES вече го има).
- Ако няма по-нова версия, сървърът може да върне `version_code` ≤ текущия или `0`.

## Жетон (подписан от сървъра)

```
token   = base64url(payload) "." base64url(signature)
payload = {"v":1,"lic":"L-2026-000123","dev":"7F3A91C20B55D1E4","plan":"pro",
           "mods":["timer","music","pulse","ai","band"],"feat":["arms_full"],
           "iat":1790000000,"exp":1821536000}
signature = ECDSA P-256, SHA-256, DER; подписва се ASCII низът base64url(payload)
```

- `exp` = 0 означава без срок.
- `dev` трябва да е `device_id` на устройството, иначе жетонът се отхвърля.
- Клиентът приема само жетони, подписани с частния ключ на сървъра. Публичният ключ (X.509 SubjectPublicKeyInfo, base64) се слага в `XemsLicense.SERVER_PUBLIC_KEY` при първия реален сървър. Докато е празен, сървърни жетони не се приемат. Така някой, който си направи собствен сървър, не може да отключи модули.
- **Частният ключ се пази само на сървъра.** Не влиза в хранилището.

## Какво остава за сървъра

1. Двойка ключове ECDSA P-256. Публичният отива в `SERVER_PUBLIC_KEY` при следващата версия на приложението.
2. База: ключове (`key`, `plan`, `mods`, `max_devices`, `expires_at`, `status`), активации (`key`, `device_id`, `device_model`, `first_seen`, `last_seen`, `app_version`).
3. Трите заявки по-горе, плюс канал за издания (APK + sha256 + notes).
4. Адресът се слага в `DEFAULT_SERVER` или се въвежда в Настройки → „Сървър ›“.

## Проверки (без Android)

- Правилата: нова инсталация = базов режим; код = всичко; сървър = само неговите модули; изтекъл преди 3 дни = работи; преди 8 дни = заключен; `exp` 0 = без срок.
- Жетон, подписан с истинска двойка ECDSA ключове: приема се. Отхвърлят се: чуждо устройство, редактиран payload с повече модули, подпис с друг ключ, липсващ ключ на сървъра.
- Разчитане на отговор за обновяване, включително `\uXXXX` и вложен обект.
